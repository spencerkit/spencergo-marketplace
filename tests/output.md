# 命名技能 (Naming Skill)

## 使用方法

当用户需要为某个事物起名时，使用这个skill。支持以下场景：
- 项目/产品命名
- 代码变量/函数/类命名
- 文件/文件夹命名
- 人名（中文名/英文名/花名）
- 宝宝小名（乳名）
- 宠物名
- 小说/角色名
- 品牌/公司名
- 书名/小说篇名
- 音乐/艺术作品名
- 游戏ID/昵称
- 网名/ID
- 公众号/自媒体名称
- 小红书/抖音/B站账号名
- 短视频标题/脚本标题
- 淘宝店铺名
- App应用名
- 域名
- 商标/品牌Logo名
- 菜名/餐厅名
- 节目/栏目名
- 活动/赛事名
- 日语/韩语名字
- 粤语/闽南语名字
- 植物名（花名/树名）
- 其他任意场景

## 询问流程（必须执行）

**第一步：识别场景类型**

首先判断用户想要为什么类型的事物起名，然后根据场景选择对应的追问分支：

### 场景类型及追问分支

#### A. 项目/产品命名
**追问问题（依次问）：**
1. 这个项目/产品的核心功能是什么？
2. 目标用户是谁？
3. 想要什么风格的命名？
   - 科技感：简洁、英文、国际化
   - 中国风：古典、诗词、典故
   - 亲切感：温暖、易懂、接地气
   - 高端大气：专业、权威、有辨识度
   - 创意独特：新颖、与众不同
   - 动物/自然：借助自然元素
4. 有什么关键词想要体现？（可选）
5. 有没有参考的名字风格？（可选）
6. 需要中文名、英文名还是中英双语？（默认双语）

#### B. 代码命名
**追问问题（依次问）：**
1. 这个变量/函数/类/常量的用途是什么？
2. 使用的编程语言是什么？（用于确定命名风格）
3. 有什么特定的命名风格要求吗？（可选）
4. 项目中有没有类似的命名可以参考？（可选）

#### C. 文件/文件夹命名
**追问问题（依次问）：**
1. 这个文件/文件夹的主要功能是什么？
2. 文件类型/文件夹用途是什么？（如.ts, .tsx, .py, .js等，或用于存放什么）
3. 有什么特定的命名风格要求吗？（可选）

#### D. 人名（中文名/英文名/花名）
**追问问题（依次问）：**
1. 是男孩名、女孩名还是中性名？

5. 有什么属相/生肖偏好？（可选，如龙、兔等）
6. 有星座偏好吗？（可选）
7. 喜欢什么风格？

   - 英文名风格：经典优雅/现代简约/复古怀旧/自然清新/独特个性
8. 想要什么调性？（可选）
   - 写实：贴近生活，真实自然
   - 文艺：优雅、有内涵、气质
   - 仙气：空灵、脱俗、意境
   - 二次元：可爱、萌系、动漫感
   - 武侠：江湖气息、豪爽大气
   - 霸总：总裁范、高冷贵气
   - 甜美：温柔、可爱、少女感
   - 硬朗：阳刚、力量、坚毅
   - 神秘：低调、内敛、难测
   - 复古：怀旧、经典、有年代感
9. 如果偏好古典风格，想要什么类型的灵感来源？（古诗词/成语典故/楚辞诗经/唐诗宋词/散文小说/历史人物）
10. 姓氏是什么？（可选，用于组合格式）

## 工作流程

**重要：必须按照以下流程执行**

1. **识别场景** - 根据用户的初始请求判断场景类型
2. **选择分支** - 从对应的追问分支开始
3. **依次追问** - 一次只问一个问题，等待用户回答后再问下一个
   - **可选问题**：用户可以回答"跳过"或"不用了"直接进入下一题
   - **并行处理**：如果用户一次回答了多个问题，可以同时处理并继续问下一个
4. **生成名称** - 信息收集完后生成候选
5. **展示结果** - 以表格形式展示，包含名称和解释
6. **等待选择** - 询问用户更喜欢哪个，或有什么修改意见
7. **微调支持** - 用户选择后可继续优化（换风格、换语言、加字等）

### 追问逻辑优化

**跳过机制：**
- 标注为"可选"的问题，用户可以回答"跳过"、"不用"、"下一题"等跳过
- 跳过后续可选问题后，直接进入生成环节

**并行处理：**
- 如果用户一次回答了多个问题（如"我叫张三，想给儿子起名，男孩"），可以同时提取：
  - 场景类型：人名
  - 姓氏：张
  - 性别：男孩
- 然后继续问下一个未回答的必要问题

**追问技巧：**
- 尽量用选择题形式，减少用户思考负担
- 根据用户回答灵活调整问题顺序
- 可以在问题中加入简单的寒暄，让对话更自然

### 追问逻辑示例

**场景：用户说"帮我起个名字"**

1. 先问："你是要起什么类型的名字？比如项目名、代码名、人名、宠物名、品牌名、小说角色名、游戏ID等？"

2. 用户回答后，选择对应分支：

## 输入识别

根据用户输入自动识别场景类型：
1. **描述式** - 用户描述一个想法/概念，如"一个帮助程序员起名的工具"

3. **参考式** - 用户给一个参考名称，如"帮我起一个类似 Claude 的名字"

## 语言判断

- 默认输出中英文双语
- 如果用户明确指定只用中文或只用英文，按用户要求
- 自动检测用户输入的语言风格

## 命名原则

根据场景应用以下原则：

**通用原则：**
- 简洁易记，发音流畅
- 无负面含义，无歧义
- 符合行业惯例

**项目/产品名：**
- 有辨识度，易于传播
- 体现核心价值或特性
- 域名和社交媒体可用

**代码命名：**
- 变量名：描述性强，简洁（camelCase）
- 函数名：动词开头，描述动作（camelCase）
- 类名：名词开头，大驼峰（PascalCase）
- 常量：全大写下划线（UPPER_SNAKE_CASE）

**文件命名：**
- 简洁描述文件内容
- 使用kebab-case或小写下划线
- 避免特殊字符

## 工作流程

**重要：必须按照以下流程执行**

1. **识别场景** - 根据用户的初始请求判断场景类型
2. **选择分支** - 从对应的追问分支开始
3. **依次追问** - 一次只问一个问题，等待用户回答后再问下一个
   - **可选问题**：用户可以回答"跳过"或"不用了"直接进入下一题
   - **并行处理**：如果用户一次回答了多个问题，可以同时处理并继续问下一个
4. **生成名称** - 信息收集完后生成候选
5. **展示结果** - 以表格形式展示，包含名称和解释
6. **等待选择** - 询问用户更喜欢哪个，或有什么修改意见
7. **微调支持** - 用户选择后可继续优化（换风格、换语言、加字等）

### 追问逻辑优化

**跳过机制：**
- 标注为"可选"的问题，用户可以回答"跳过"、"不用"、"下一题"等跳过
- 跳过后续可选问题后，直接进入生成环节

**并行处理：**
- 如果用户一次回答了多个问题（如"我叫张三，想给儿子起名，男孩"），可以同时提取：
  - 场景类型：人名
  - 姓氏：张
  - 性别：男孩
- 然后继续问下一个未回答的必要问题

**追问技巧：**
- 尽量用选择题形式，减少用户思考负担
- 根据用户回答灵活调整问题顺序
- 可以在问题中加入简单的寒暄，让对话更自然

### 追问逻辑示例

**场景：用户说"帮我起个名字"**

1. 先问："你是要起什么类型的名字？比如项目名、代码名、人名、宠物名、品牌名、小说角色名、游戏ID等？"

2. 用户回答后，选择对应分支：
   - 如果用户说"一个产品名" → 走 A.项目/产品命名 分支
   - 如果用户说"帮我家猫起名" → 走 E.宠物名 分支
   - 如果用户说"起个人名" → 走 D.人名 分支

3. 按分支顺序追问，根据用户回答灵活调整

### 名字禁忌（必读）

起名时需要注意以下禁忌：

**中文名禁忌：**
- 谐音歧义：避免与不雅词汇谐音（如"史珍香"、"杜子腾"等）
- 生僻字：避免过于复杂的字，影响日常使用
- 多音字：避免容易读错的字
- 负面含义：避免消极、不吉利的字义
- 祖先名：避免与祖辈名字重复（部分地区习俗）
- 同音不同字：注意同音词的歧义

**英文名禁忌：**
- 奇怪含义：避免有不良含义的单词
- 难以发音：避免太长的名字
- 文化禁忌：避免在目标国家/文化中有负面含义的名字
- 与品牌冲突：避免与知名品牌重名

**品牌名禁忌：**
- 商标侵权：避免与已有商标近似
- 行业通用词：避免过于通用的词汇
- 政治敏感：避免涉及政治元素
- 宗教禁忌：避免涉及宗教元素
