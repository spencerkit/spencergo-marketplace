# 写作技能 V2 (Writing Skill)

## 核心改进

- **6阶段协作流程** - 从单向输出变为全程协作
- **Demo确认机制** - 风格确定前先输出小样预览
- **章节确认机制** - 用户选择确认粒度
- **审核机制** - 模拟读者提问验证内容
- **风格复核** - 对比Demo与最终文章确保一致

## 使用方法

```
/写作
```

或直接描述需求，如：
- "帮我写一篇公众号文章"
- "写一个关于xxx的故事"
- "帮我写技术教程"

## 写作流程（6阶段）

| 阶段 | 名称 | 核心内容 |
|------|------|----------|
| 1 | 需求理解 | 目的、背景、观点、读者、内容概要、**交付方式** |
| 2 | 大纲讨论 | 3-5个大纲选项 → 用户选择 → **确认大纲** |
| 3 | 风格确认 | 偏好提问 → **生成200字Demo** → 用户评审 → **确认风格** |
| 4 | 分节写作 | 用户选择确认粒度（A/B/C）→ 写作 → 确认 |
| 5 | 审核 | AI推测问题 + 用户补充 + 修改 |
| 6 | 风格复核 + 交付 | 风格对比 + 自动修正 + 最终审核 |

> **注意**：以上6阶段流程适用于所有内容类型（公众号文章、小红书、技术教程、故事小说等）。内容类型的差异会在需求理解阶段通过提问来识别，并融入到后续各阶段中。

## 详细流程

### 第一阶段：需求理解

**目的**：深入了解用户写文章的背景和需求

**提问**（依次进行，用户可一次性回答多个）：

1. **文章目的**：这篇文章用来做什么？（如：分享经验、记录生活、产品宣传）
2. **写作背景**：为什么写这篇文章？有什么特别的原因或契机？
3. **核心观点**：想传达什么观点或信息？
4. **目标读者**：谁会读这篇文章？（如：技术人员、创业者、小白用户）
5. **内容概要**：大致想写哪些内容？（用户自由描述）
6. **字数预期**：大概想要多长的文章？（如：1000字/2000字/3000字+）

**交付方式确认**（必须追问）：

> 你想要怎么交付？
> - A. 一次性写完整篇 → 整体确认
> - B. 先出大纲 → 确认后写正文 → 确认
> - C. 按章节写 → 写一章确认一章

**输出**：整理成需求摘要，与用户确认后进入下一阶段

---

### 第二阶段：大纲讨论

**目的**：确定文章结构

> ⚠️ **此阶段不可跳过** - 必须先确认大纲才能进入风格确认和写作阶段

1. **生成大纲**：根据需求生成 3-5 个大纲选项（每个大纲 3-5 个章节）
2. **用户选择/修改**：用户选择某个大纲，或对大纲提出修改意见
3. **确认大纲**：用户明确确认"大纲OK"或"可以"后，才能进入下一阶段

**输出**：
```
## 大纲选项

### 选项A
1. 第一章：xxx
2. 第二章：xxx
3. 第三章：xxx

### 选项B
...

---

// 用户选择后
## 确认的大纲

1. 第一章：xxx
2. 第二章：xxx
3. 第三章：xxx

---
✅ 大纲已确认，进入风格确认阶段
```

---

### 第三阶段：风格确认（核心改进）

**目的**：确定文章风格，生成 Demo 预览

> ⚠️ **此阶段不可跳过** - 必须先确认 Demo 风格后才能进入写作阶段

**步骤 3.1：提问偏好**

无论有没有参考模板，都需要提问：

1. **心情/情绪**：想用什么心情/语气写？（如：轻松活泼、严肃专业、温暖治愈、犀利深刻）
2. **习惯表达**：喜欢长句还是短句？喜欢用什么类型的词汇？（如：专业术语、口语化、接地气、文绉绉）
3. **性格特点**：想呈现什么性格？（如：理性、感性、幽默、温暖、犀利）
4. **形象定位**：希望读者觉得作者是什么样的人？（如：专家权威、平易近人的朋友、leader、创业者）

**步骤 3.2：参考来源（可选）**

- 问：有没有参考的模板/文章/作者风格？
  - 有 → 分析用户提供的内容，提取风格特点，融入步骤 3.1
  - 无 → 跳过

**步骤 3.3：生成 Demo**

> ⚠️ **必须生成 Demo** - 基于以上信息，生成 **200字左右** 的 Demo
> Demo 应覆盖：开头风格、叙事节奏、句式特点、关键词使用

**步骤 3.4：用户评审 Demo**

> ⚠️ **必须让用户明确确认** - 用户说"可以"、"OK"、"风格对了"才能进入下一阶段

- 用户阅读 Demo，提出修改意见
- 不符合 → 修改 Demo → 重新生成 Demo → 再次评审
- **通过** → 进入下一阶段（需要用户明确说"可以"或"OK"）

**输出**：
```
## 风格偏好

- 心情：xxx
- 句式：xxx
- 性格：xxx
- 形象：xxx
- 参考：xxx

---

### Demo 预览（约200字）

{200字左右的Demo}

---

请评审 Demo，告诉我：
1. 风格是否符合你的预期？
2. 需要调整哪些地方？

// 用户确认"可以"或"OK"后
✅ 风格已确认，进入写作阶段
```

---

### 第四阶段：分节写作

**目的**：按章节写作，用户全程参与

**步骤 4.1：选择确认方式**

通过提问让用户选择：

1. **A. 每节确认** - 写完一小节就确认
2. **B. 部分确认** - 几个部分确认一次（如：开头+3个论点+结尾）
3. **C. 整体确认** - 写完初稿后整体确认

**步骤 4.2：按选择执行**

- 选择 A：写一章 → 用户确认 → 下一章 → ... → 整体润色
- 选择 B：写一部分 → 用户确认 → 下一部分 → ... → 整体润色
- 选择 C：直接写完整初稿 → 用户审核

**输出**：完整初稿

---

### 第五阶段：审核

**目的**：验证文章是否回答了核心问题

**步骤 5.1：AI 推测问题**

- 根据文章内容，推测 "读者可能问的 3-5 个问题"
- 列出这些问题

**步骤 5.2：检查覆盖**

- 对比文章内容，检查是否回答了这些问题
- 标注已回答/未回答的问题

**步骤 5.3：用户补充（可选）**

- 用户可以补充自己的问题
- 也可以跳过此步骤

**步骤 5.4：根据审核修改**

- 根据问题列表，修改文章
- 与用户确认修改结果

**输出**：
```
## 审核结果

### 推测问题
1. 问题1 - 已回答/未回答
2. 问题2 - 已回答/未回答
...

### 用户补充问题（如有）
1. 问题X - 已回答/未回答
...

### 修改内容
{修改说明}
```

---

### 第六阶段：风格复核 + 最终交付

**目的**：确保风格一致性，最终交付

**步骤 6.1：风格对比**

- 对比 Demo 风格与最终文章
- 检查：语气、句式、结构、关键词使用

**步骤 6.2：自动修正**

- 如风格不符，自动修改直到一致

**步骤 6.3：用户最终审核**

- 用户阅读最终版本
- 提供修改意见（或直接通过）

**步骤 6.4：交付**

- 输出最终文章
- 提供后续优化建议

## 上下文处理

### 上下文类型识别

| 类型 | 识别方式 | 处理方式 |
|------|----------|----------|
| **纯文本** | 用户直接粘贴 | 直接使用 |
| **仓库地址** | URL包含github.com/gitlab.com | git clone → 分析代码结构 |
| **文件路径** | 本地路径格式 | 读取文件内容 |
| **无上下文** | 用户未提供 | 使用默认处理 |

### 仓库分析流程

当用户提供仓库地址时：
1. 解析仓库URL
2. Clone到临时目录
3. 分析项目结构
4. 提取关键技术信息：
   - 编程语言
   - 框架/库
   - 目录结构
   - 核心模块
5. 整理成上下文摘要
6. 融入写作 prompt

### 文件读取处理

当用户提供文件路径时：
1. 验证文件存在
2. 读取文件内容
3. 识别文件类型
4. 提取关键信息
5. 融入写作 prompt

### 技术文章上下文模板

请基于以下上下文信息写一篇技术文章：

仓库/文件上下文：
{上下文内容}

主题：{主题}
类型：{类型}
读者水平：{水平}

要求：
1. 基于提供的上下文进行分析
2. 结合实际代码示例
3. 内容准确，专业
4. 解释清晰易懂

## D. 润色功能模块

### D1. 触发识别

当用户表达以下意图时，进入润色模式：
- 改写、重写、润色、优化、校对
- "帮我改一下"、"这篇不太好"
- 粘贴文章 + "怎么样"

### D2. 润色类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| **改写** | 不同风格/语气重写 | 风格不满意、需要不同调性 |
| **优化** | 改进内容质量 | 内容还行，想更好 |
| **校对** | 语法/错别字/格式 | 需要检查修正 |

### D3. 通用润色追问

1. 这是什么类型的文章？（或自动识别）
2. 你想要什么效果？
   - 改写：改成什么风格？（如：严肃→轻松，专业→通俗）
   - 优化：哪方面？（更有说服力/更简洁/更有趣）
   - 校对：只需要检查错别字还是全面检查？
3. 想要什么方式进行润色？
   - A. 参考风格样本 - 提供你之前写的文章，我按该风格润色
   - B. 指定风格 - 直接选择目标风格（严肃/轻松/幽默等）
   - C. 直接润色 - 不需要特定风格
4. 有特别关注的重点吗？（可选）

如果用户选择 A，触发 F. 风格样本分析模块。

### D4. 各类型润色要点

**公众号/博客文章：**
- 标题吸引力
- 开头抓人程度
- 内容深度
- 结尾引导

**小红书：**
- emoji使用
- 话题标签
- 情感共鸣
- 互动引导

**技术文章：**
- 代码准确性
- 解释清晰度
- 步骤完整性

**故事/小说：**
- 人物刻画
- 情节张力
- 语言风格

## F. 风格样本分析模块

### F1. 功能概述

用户可以提供自己写的文章作为风格样本，AI 分析这些文章的风格特点，然后生成/润色时模仿这种风格，减少"AI 感"。

### F2. 应用场景

1. **写作时参考风格** - 用户想写新文章时，提供样本让 AI 模仿风格
2. **润色时参考风格** - 用户有初稿，提供样本让 AI 按该风格润色

### F3. 触发场景

当用户：
- 在写作时说"参考我的风格"、"按我的风格写"
- 在润色时说"参考我之前的文章"
- 直接提供文章内容说"按这个风格"
- 回答可选追问时说"有，我的风格是..."

### F4. 输入方式

| 类型 | 识别方式 | 处理方式 |
|------|----------|----------|
| **直接粘贴** | 用户复制文章内容 | 直接分析 |
| **文件路径** | 本地路径格式 | 读取文件内容 |
| **仓库地址** | GitHub URL | 获取文件内容 |

### F5. 限制

- 样本数量：1-3篇
- 每篇长度：建议 500-3000 字
- 超出范围可以只分析部分内容

### F6. 风格分析要素

**核心要素（必分析）：**
- 用词习惯 - 专业术语/口语化/接地气/文言化
- 句子长短 - 长句多/短句多/长短交替
- 段落结构 - 段落长度、层次安排

**扩展要素（如有）：**
- 语气特点 - 严肃/轻松/俏皮/温暖/犀利
- 开头方式 - 直入主题/故事引入/提问引入/结论先行
- 结尾方式 - 总结/升华/开放/互动/金句点睛
- 叙事节奏 - 快/慢/张弛有度
- 个人特色 - 特色词/口头禅/习惯表达

### F7. 风格分析 prompt 模板

文章内容：
{文章内容}

2. 句子长短 - 长句多还是短句多？还是交替？
3. 段落结构 - 段落长度如何？层次怎么安排？

**扩展要素（如有）：**

6. 结尾方式 - 总结/升华/开放/互动/金句点睛？

## 追问技巧

1. **一次只问一个问题**，等待用户回答后再问下一个
2. **优先用选择题**，减少用户思考负担
3. **可选问题标注清楚**，用户可以跳过
4. **并行处理**：如果用户一次回答了多个问题，同时处理
5. **记住上下文**：之前的回答自动带入后续问题
