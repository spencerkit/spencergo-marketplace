# 写作技能 V4 (Writing Skill - 混合模式)

## 模块架构

```
writing (主Skill)
├── writing-style    → 风格分析
├── writing-outline  → 大纲编写
├── writing-content  → 内容编写
├── writing-review   → 内容审核
└── writing-polish   → 润色
```

## 预设模板

| 模板 | 包含模块 | 适用场景 |
|------|----------|----------|
| 完整写作 | style → outline → content → review → polish | 从头写完整文章 |
| 快速写作 | style → content | 短内容、熟悉主题 |
| 仅润色 | polish | 已有初稿只需润色 |
| 审核+润色 | review → polish | 写完了想审核+优化 |

## 独立调用

用户也可以直接调用任意子模块：
- `/writing-style` - 风格分析
- `/writing-outline` - 大纲编写
- `/writing-content` - 内容编写
- `/writing-review` - 内容审核
- `/writing-polish` - 润色

## 流程指引（Claude 自动串联）

**按照以下顺序调用子模块，每个阶段完成后必须明确引导用户进入下一步：**

### 完整流程
1. **风格分析阶段** → 用户确认风格后 → 说"继续"或"下一步" → **invoke /writing-outline**
2. **大纲编写阶段** → 用户确认大纲后 → 说"继续"或"开始写作" → **invoke /writing-content**
3. **内容编写阶段** → 用户确认初稿后 → 说"继续"或"帮我审核" → **invoke /writing-review**
4. **内容审核阶段** → 用户确认审核结果后 → 说"继续"或"润色" → **invoke /writing-polish**
5. **润色阶段** → 用户确认润色结果后 → 交付完成

### 关键规则

- **不要跳过任何阶段**（除非用户明确要求快速模式）
- **每个阶段必须获得用户确认**后才能进入下一阶段
- **不要在内容编写阶段就调用审核**，必须等用户确认初稿
- **不要在审核阶段就自动润色**，必须等用户确认审核结果

## 写作流程（标准模式 - 6阶段）

| 阶段 | 名称 | 核心内容 | 进度 |
|------|------|----------|------|
| 1 | 需求理解 | 目的、背景、观点、读者、内容概要、**写作节奏** | [1/6] |
| 2 | 大纲讨论 | 3-5个大纲选项 → 用户选择 → **确认大纲** | [2/6] |
| 3 | 风格确认 | 偏好提问 → **生成动态Demo** → 用户评审 → **确认风格** | [3/6] |
| 4 | 分节写作 | 按节奏写作 → **实时风格对比** → **嵌入式自检** → 确认 | [4/6] |
| 5 | 审核 | AI推测问题 + 用户补充 + 修改 | [5/6] |
| 6 | 风格复核 + 交付 | 风格对比 + 自动修正 + 最终审核 | [6/6] |

> **注意**：
> - 每个阶段开始时显示进度（如 [2/6] 大纲讨论）
> - 任何阶段可输入"返回上一步"进行调整
> - 内容类型差异在需求理解阶段识别，并融入后续各阶段

## 详细流程

### 第一阶段：需求理解 [1/6]

**目的**：深入了解用户写文章的背景和需求

**提问**（依次进行，用户可一次性回答多个）：

1. **内容类型**：写什么类型的内容？（公众号/小红书/技术教程/故事/短视频脚本）
2. **文章目的**：这篇文章用来做什么？（如：分享经验、记录生活、产品宣传）
3. **写作背景**：为什么写这篇文章？有什么特别的原因或契机？
4. **核心观点**：想传达什么观点或信息？
5. **目标读者**：谁会读这篇文章？（如：技术人员、创业者、小白用户）
6. **内容概要**：大致想写哪些内容？（用户自由描述）
7. **字数预期**：大概想要多长的文章？（如：500字/1000字/2000字/3000字+）

**写作节奏确认**（必须追问）：

> 你希望怎样的写作节奏？
> - A. 每节确认 - 写一节确认一节（适合长文章、重要内容）
> - B. 分段确认 - 写几节后确认一次（适合中等长度）
> - C. 整体确认 - 一次性写完再确认（适合短文、熟悉的主题）

**模式判断**：
- 如果字数 < 500 或内容类型为小红书/微博 → 提示"检测到简短内容，将使用快速模式（跳过大纲讨论和审核阶段），是否继续？"

**输出**：整理成需求摘要，与用户确认后进入下一阶段

> 💡 **随时可以返回**：输入"返回上一步"可重新调整需求

---

### 第二阶段：大纲讨论 [2/6]

**目的**：确定文章结构

> ⚠️ **快速模式跳过此阶段** - 直接进入风格确认

1. **生成大纲**：根据需求生成 3-5 个大纲选项（每个大纲 3-5 个章节）
2. **用户选择/修改**：用户选择某个大纲，或对大纲提出修改意见
3. **确认大纲**：用户明确确认"大纲OK"或"可以"后，才能进入下一阶段

> 💡 **随时可以返回**：输入"返回上一步"可重新调整需求

**输出**：
```
## 大纲选项

### 选项A
1. 第一章：xxx
2. 第二章：xxx
3. 第三章：xxx

### 选项B
...

---

// 用户选择后
## 确认的大纲

1. 第一章：xxx
2. 第二章：xxx
3. 第三章：xxx

---
✅ 大纲已确认，进入风格确认阶段
```

---

### 第三阶段：风格确认 [3/6]

**目的**：确定文章风格，生成 Demo 预览

**步骤 3.1：提问偏好**

无论有没有参考模板，都需要提问：

1. **心情/情绪**：想用什么心情/语气写？（如：轻松活泼、严肃专业、温暖治愈、犀利深刻）
2. **习惯表达**：喜欢长句还是短句？喜欢用什么类型的词汇？（如：专业术语、口语化、接地气、文绉绉）
3. **性格特点**：想呈现什么性格？（如：理性、感性、幽默、温暖、犀利）
4. **形象定位**：希望读者觉得作者是什么样的人？（如：专家权威、平易近人的朋友、leader、创业者）

**步骤 3.2：参考来源（可选）**

- 问：有没有参考的模板/文章/作者风格？
  - 有 → 分析用户提供的内容，提取风格特点，融入步骤 3.1
  - 无 → 跳过

**步骤 3.3：生成动态Demo**

> ⚠️ **必须生成 Demo** - 根据内容类型生成不同长度的Demo

| 内容类型 | Demo长度 | Demo内容 |
|---------|---------|---------|
| 小红书/微博 | 100-150字 | 完整开头段落 |
| 公众号文章 | 200-300字 | 开头+第一小节 |
| 技术教程 | 300-400字 | 开头+代码示例 |
| 故事小说 | 300-400字 | 完整场景描写 |
| 短视频脚本 | 完整开场 | 镜头描述+台词 |

**步骤 3.4：用户评审 Demo**

> ⚠️ **必须让用户明确确认** - 用户说"可以"、"OK"、"风格对了"才能进入下一阶段

- 用户阅读 Demo，提出修改意见
- 不符合 → 修改 Demo → 重新生成 Demo → 再次评审
- **通过** → 进入下一阶段（需要用户明确说"可以"或"OK"）

> 💡 **随时可以返回**：输入"返回上一步"可重新选择大纲

**输出**：
```
## 风格偏好

- 心情：xxx
- 句式：xxx
- 性格：xxx
- 形象：xxx
- 参考：xxx

---

### Demo 预览（约200字）

{200字左右的Demo}

---

请评审 Demo，告诉我：
1. 风格是否符合你的预期？
2. 需要调整哪些地方？

// 用户确认"可以"或"OK"后
✅ 风格已确认，进入写作阶段
```

---

### 第四阶段：分节写作 [4/6]

**目的**：按章节写作，用户全程参与

**步骤 4.1：按第一阶段确认的节奏执行**

根据用户在第一阶段选择的写作节奏：

- **选择 A（每节确认）**：写一章 → **实时风格对比** → **嵌入式自检** → 用户确认 → 下一章
- **选择 B（分段确认）**：写一部分 → **实时风格对比** → **嵌入式自检** → 用户确认 → 下一部分
- **选择 C（整体确认）**：直接写完整初稿 → **实时风格对比** → **嵌入式自检** → 用户审核

**实时风格对比**：
- 每写完一节，自动对比Demo风格
- 检查：语气、句式、关键词使用是否一致
- 如有偏离，自动微调

**嵌入式自检**：

1. **逻辑检查**
   - 逻辑是否清晰？
   - 是否有未解释的概念？
   - 是否符合目标读者水平？

2. **AI 模式检测**（必须检查）
   - [ ] 是否使用了"此外""然而""值得注意的是"等填充短语？
   - [ ] 是否有三段式列举（连续三个"第一/第二/第三"或"一方面...另一方面...一方面..."）？
   - [ ] 是否有过多破折号（超过2个）？
   - [ ] 句子长度是否过于一致（无变化）？
   - [ ] 是否有"是...的证明/体现/标志"等浮夸表达？
   - [ ] 是否有"行业专家""多项研究表明"等模糊归因？

   如有以上问题，自动修改后再提交用户审核。

**输出**：完整初稿

> 💡 **随时可以返回**：输入"返回上一步"可重新确认风格

---

### 第五阶段：审核 [5/6]

**目的**：验证文章是否回答了核心问题

> ⚠️ **快速模式跳过此阶段** - 直接进入交付

**步骤 5.1：AI 推测问题**

- 根据文章内容，推测 "读者可能问的 3-5 个问题"
- 列出这些问题

**步骤 5.2：检查覆盖**

- 对比文章内容，检查是否回答了这些问题
- 标注已回答/未回答的问题

**步骤 5.3：用户补充（可选）**

- 用户可以补充自己的问题
- 也可以跳过此步骤

**步骤 5.4：根据审核修改**

- 根据问题列表，修改文章
- 与用户确认修改结果

> 💡 **随时可以返回**：输入"返回上一步"可重新调整写作内容

**输出**：
```
## 审核结果

### 推测问题
1. 问题1 - 已回答/未回答
2. 问题2 - 已回答/未回答
...

### 用户补充问题（如有）
1. 问题X - 已回答/未回答
...

### 修改内容
{修改说明}
```

---

### 第六阶段：风格复核 + 最终交付 [6/6]

**目的**：确保风格一致性，最终交付

**步骤 6.1：风格对比**

- 对比 Demo 风格与最终文章
- 检查：语气、句式、结构、关键词使用
- **AI 痕迹检查清单**（必须逐项确认）：
  - [ ] 无连续三个相同长度的句子
  - [ ] 段落结尾方式多样（不都是总结句）
  - [ ] 无破折号过度使用
  - [ ] 无"此外""然而""值得注意的"等填充短语
  - [ ] 无三段式列举
  - [ ] 无"是...的证明/体现/标志"等浮夸表达
  - [ ] 无"行业专家""多项研究表明"等模糊归因
  - [ ] 无聊天机器人语气（"希望对您有帮助""请告诉我"）

**步骤 6.2：自动修正**

- 如风格不符或 AI 痕迹检测未通过，自动修改直到一致

**步骤 6.3：用户最终审核**

- 用户阅读最终版本
- 提供修改意见（或直接通过）

**步骤 6.4：交付**

- 输出最终文章
- 提供后续优化建议

> 💡 **随时可以返回**：输入"返回上一步"可重新审核内容

## 上下文处理

### 上下文类型识别

| 类型 | 识别方式 | 处理方式 |
|------|----------|----------|
| **纯文本** | 用户直接粘贴 | 直接使用 |
| **仓库地址** | URL包含github.com/gitlab.com | git clone → 分析代码结构 |
| **文件路径** | 本地路径格式 | 读取文件内容 |
| **无上下文** | 用户未提供 | 使用默认处理 |

### 仓库分析流程

当用户提供仓库地址时：
1. 解析仓库URL
2. Clone到临时目录
3. 分析项目结构
4. 提取关键技术信息：
   - 编程语言
   - 框架/库
   - 目录结构
   - 核心模块
5. 整理成上下文摘要
6. 融入写作 prompt

### 文件读取处理

当用户提供文件路径时：
1. 验证文件存在
2. 读取文件内容
3. 识别文件类型
4. 提取关键信息
5. 融入写作 prompt

### 技术文章上下文模板

请基于以下上下文信息写一篇技术文章：

仓库/文件上下文：
{上下文内容}

主题：{主题}
类型：{类型}
读者水平：{水平}

要求：
1. 基于提供的上下文进行分析
2. 结合实际代码示例
3. 内容准确，专业
4. 解释清晰易懂

## D. 润色功能模块

### D1. 触发识别

当用户表达以下意图时，进入润色模式：
- 改写、重写、润色、优化、校对
- "帮我改一下"、"这篇不太好"
- 粘贴文章 + "怎么样"

### D2. 润色类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| **改写** | 不同风格/语气重写 | 风格不满意、需要不同调性 |
| **优化** | 改进内容质量 | 内容还行，想更好 |
| **校对** | 语法/错别字/格式 | 需要检查修正 |
| **去 AI 化** | 去除 AI 写作痕迹，注入人性 | AI 生成内容、听起来像机器写的 |

### D3. 通用润色追问

1. 这是什么类型的文章？（或自动识别）
2. 你想要什么效果？
   - 改写：改成什么风格？（如：严肃→轻松，专业→通俗）
   - 优化：哪方面？（更有说服力/更简洁/更有趣）
   - 校对：只需要检查错别字还是全面检查？
   - 去 AI 化：去除 AI 写作痕迹，变得更像人写的
3. 想要什么方式进行润色？
   - A. 参考风格样本 - 提供你之前写的文章，我按该风格润色
   - B. 指定风格 - 直接选择目标风格（严肃/轻松/幽默等）
   - C. 直接润色 - 不需要特定风格
4. 有特别关注的重点吗？（可选）

如果用户选择 A，触发 F. 风格样本分析模块。

### D4. 各类型润色要点

**公众号/博客文章：**
- 标题吸引力
- 开头抓人程度
- 内容深度
- 结尾引导

**小红书：**
- emoji使用
- 话题标签
- 情感共鸣
- 互动引导

**技术文章：**
- 代码准确性
- 解释清晰度
- 步骤完整性

**故事/小说：**
- 人物刻画
- 情节张力
- 语言风格

**去 AI 化：**
- 去除填充短语（"此外""值得注意的是""总的来说"）
- 打破公式结构（避免三段式、否定式排比）
- 变化句子节奏（长短交替）
- 删除浮夸表达（"是...的证明""标志性的时刻"）
- 移除模糊归因（"专家表示""多项研究表明"）
- 去除聊天机器人语气
- 注入个性：有观点、承认复杂性、适当使用第一人称

要求：

2. 检查语法错误
3. 检查格式问题
4. 列出所有修改点及原因
5. 给出校对后的完整版本

### D9. 去 AI 化 prompt 模板

请去除以下文章中的 AI 写作痕迹，使其听起来更像人类书写：

原文：
{原文内容}

要求：
1. **删除填充短语**：去除"此外""然而""值得注意的是""总的来说""需要注意的是"等开场白
2. **打破公式结构**：避免"不仅...而且..."、"第一/第二/第三"三段式列举
3. **变化句子节奏**：混合句子长度，避免每句都长度一致
4. **删除浮夸表达**：去除"是...的证明/体现/标志"、"标志着...重要时刻"、"关键转折点"等
5. **移除模糊归因**：去除"专家表示""多项研究表明""行业观察者认为"等无具体来源的表述
6. **去除破折号过度使用**：删除不必要的破折号
7. **去除聊天机器人语气**：删除"希望对您有帮助""请告诉我""如果您需要..."等对话痕迹
8. **注入人性**：
   - 有观点（不只是中立报道）
   - 承认复杂性（不只是简单总结）
   - 适当使用第一人称
   - 允许轻微混乱（跑题、题外话是人性的体现）

保持原文核心内容不变，只改变表达方式。

## F. 风格样本分析模块

### F1. 功能概述

用户可以提供自己写的文章作为风格样本，AI 分析这些文章的风格特点，然后生成/润色时模仿这种风格，减少"AI 感"。

### F2. 应用场景

1. **写作时参考风格** - 用户想写新文章时，提供样本让 AI 模仿风格
2. **润色时参考风格** - 用户有初稿，提供样本让 AI 按该风格润色

### F3. 触发场景

当用户：
- 在写作时说"参考我的风格"、"按我的风格写"
- 在润色时说"参考我之前的文章"
- 直接提供文章内容说"按这个风格"
- 回答可选追问时说"有，我的风格是..."

### F4. 输入方式

| 类型 | 识别方式 | 处理方式 |
|------|----------|----------|
| **直接粘贴** | 用户复制文章内容 | 直接分析 |
| **文件路径** | 本地路径格式 | 读取文件内容 |
| **仓库地址** | GitHub URL | 获取文件内容 |

### F5. 限制

- 样本数量：1-3篇
- 每篇长度：建议 500-3000 字
- 超出范围可以只分析部分内容

### F6. 风格分析要素

**核心要素（必分析）：**
- 用词习惯 - 专业术语/口语化/接地气/文言化
- 句子长短 - 长句多/短句多/长短交替
- 段落结构 - 段落长度、层次安排

**扩展要素（如有）：**
- 语气特点 - 严肃/轻松/俏皮/温暖/犀利
- 开头方式 - 直入主题/故事引入/提问引入/结论先行
- 结尾方式 - 总结/升华/开放/互动/金句点睛
- 叙事节奏 - 快/慢/张弛有度
- 个人特色 - 特色词/口头禅/习惯表达

## 追问技巧

1. **一次只问一个问题**，等待用户回答后再问下一个
2. **优先用选择题**，减少用户思考负担
3. **可选问题标注清楚**，用户可以跳过
4. **并行处理**：如果用户一次回答了多个问题，同时处理
5. **记住上下文**：之前的回答自动带入后续问题
