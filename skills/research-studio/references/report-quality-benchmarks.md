# Report Quality Benchmarks

## 1. Goal

Make report quality concrete by showing the difference between a weak report, an acceptable report, and a researcher-grade report.

---

## 2. Weak report

A weak report usually has these problems:
- mostly repeats obvious facts
- says what is happening but not why
- uses generic conclusions that fit many topics
- provides recommendations with no evidence or operational path
- hides uncertainty behind smooth wording
- feels polished but not decision-useful

Typical weak phrases:
- 值得关注
- 有一定潜力
- 未来可期
- 建议进一步观察
- 应持续优化

These phrases are not automatically forbidden, but they are weak unless followed by:
- evidence
- boundaries
- mechanism
- action path

---

## 3. Acceptable report

An acceptable report:
- gives a clear conclusion
- provides some source-backed support
- distinguishes stronger and weaker evidence
- includes at least some operational recommendations
- avoids obvious fluff

But an acceptable report may still be limited if it:
- stops at surface trends
- lacks strong case support
- gives actions that are still too broad

---

## 4. Researcher-grade report

A researcher-grade report:
- answers the actual decision problem
- shows the reasoning path, not just the result
- distinguishes evidence from inference
- explains mechanism, not just trend
- uses concrete cases where they sharpen the point
- gives bounded, actionable next steps
- marks uncertainty cleanly instead of hiding it

This is the target standard for serious research delivery.

---

## 5. Quick contrast example

### Weak
"This market has some potential, but competition is also intense, so it is worth continued observation."

### Better
"Demand appears real, but current evidence suggests the harder problem is differentiation, not awareness. If you continue, validate willingness to pay before expanding the idea."

### Researcher-grade
"Current evidence supports demand existence more strongly than commercial viability. The main risk is not whether users care, but whether existing substitutes are already ‘good enough.’ That changes the correct next step: instead of building more features, test whether a narrower segment has both stronger pain and weaker substitutes."

---

## 6. Case and action benchmark

If the report gives advice, check whether it does both:
- shows a case/example or evidence basis
- tells the user what to do next in concrete sequence

If it does neither, the advice is probably too weak.

---

## 7. Final self-check

Before delivering, ask:
- did I explain why, not just what?
- did I show where the conclusion comes from?
- did I hide uncertainty behind smooth language?
- would the user know what to do next?
- could this report apply to almost any topic? If yes, tighten it.
