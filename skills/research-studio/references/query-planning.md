# Query Planning

## 1. Goal

Turn a broad topic into a set of useful search queries instead of repeating one vague query many times.

---

## 2. Core rule

Do not search the exact same phrasing over and over.
Rewrite queries based on:
- topic type
- analysis dimension
- geography or platform
- time sensitivity
- likely source type

---

## 3. Default query-planning process

### Step 1: extract the core object
Identify the main research object.
Examples:
- AI companion market
- 小红书家居内容生态
- 陪诊师
- cross-border pet supplies

### Step 2: identify the real question
What is the user actually asking?
Common underlying questions:
- what is this?
- how big or active is it?
- who wants it?
- who is already doing it?
- how does it make money?
- what are the risks?
- is it worth doing?

### Step 3: create dimension-specific queries
Create separate query lines for different dimensions.
Typical dimensions:
- definition / scope
- current state
- demand / audience
- competition / supply
- monetization
- risk / regulation / friction
- trend / recent change

### Step 4: vary query style
Vary wording using:
- exact topic terms
- synonyms
- platform-specific wording
- industry wording
- “report / data / trend / case / competitor / policy / users / monetization” terms

### Step 5: add narrowing modifiers when needed
Useful modifiers include:
- country / region
- year / recent
- platform name
- audience segment
- business model
- case study / example

---

## 4. Query buckets

For most topics, build queries in buckets.

### A. Orientation queries
Used to understand the topic quickly.
Examples:
- "AI companion market overview"
- "小红书 家居内容 现状"
- "陪诊师 行业 现状"

### B. Demand queries
Used to understand user need or appetite.
Examples:
- "AI companion user demand"
- "小红书 家居内容 用户偏好"
- "陪诊师 用户 痛点"

### C. Competition queries
Used to identify who is already there.
Examples:
- "AI companion competitors"
- "小红书 家居赛道 头部账号"
- "陪诊师 平台 服务 商家"

### D. Monetization queries
Used to understand value capture.
Examples:
- "AI companion monetization"
- "小红书 家居内容 变现"
- "陪诊师 商业模式"

### E. Risk queries
Used to find friction, policy, saturation, or failure points.
Examples:
- "AI companion risks"
- "小红书 家居内容 赛道 风险"
- "陪诊师 合规 风险"

### F. Freshness queries
Used when current conditions matter.
Examples:
- "2026 AI companion trend"
- "2026 小红书 家居内容 趋势"
- "2026 陪诊师 市场"

---

## 5. Query adaptation by topic type

### Market / industry
Favor terms like:
- market
- industry
- trend
- report
- growth
- competitors
- regulation

### Product / project
Favor terms like:
- users
- alternatives
- willingness to pay
- case study
- competitors
- business model
- execution

### Platform / content ecosystem
Favor terms like:
- audience preference
- trending topics
- creator strategy
- content saturation
- platform rules
- monetization
- distribution

---

## 6. Query-quality rule

A good search plan includes:
- one query for basic orientation
- several queries for different dimensions
- at least one freshness-sensitive query when the topic changes quickly
- at least one query aimed at stronger or more direct sources

A weak search plan is:
- one vague query repeated many times
- no dimension split
- no freshness check
- no attempt to find stronger sources
