# Intake and Alignment

## 1. Goal

Front-load all major clarification before execution so the research run does not stop halfway to ask scattered questions.

---

## 2. Core rule

Before starting the full research workflow, identify the key requirement gaps and resolve them up front.

The agent should:
- analyze the task scope first
- identify what decisions affect the whole report structure
- pressure-test the requirement tree instead of stopping at rough understanding
- ask those questions early in one batch
- confirm alignment with the user before full execution

Do not keep asking piecemeal questions after the report is already halfway done unless a truly blocking and unforeseeable issue appears.

---

## 3. What must be clarified early when relevant

Clarify as early as possible:
- target use of the report
- target audience
- depth expectation
- preferred output style
- whether the user wants strategic judgment, execution guidance, or both
- whether the user wants examples, case studies, and operational recommendations
- whether the user wants a report artifact such as HTML / PNG

---

## 4. Completion rule for intake

Do not start the main execution flow until:
- the key scope questions are answered or reasonably inferred
- the report target is clear enough
- the expected delivery form is clear enough

Use `intake-question-batch.md` when you need a compact one-shot intake pattern.

Once alignment is complete, execute the full flow without interrupting the user with unnecessary mid-process clarification.

---

## 5. Emergency exception

Only interrupt mid-process if:
- a required source is impossible to access
- a critical conflict appears in user requirements
- a blocking ambiguity appears that could invalidate the whole report
